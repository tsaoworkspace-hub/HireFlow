# 可設定簽核流程與標準職稱

> 版本範圍：本文件對應已在本機實作的擴充版本，相關程式碼尚未同步至本 Repository。目前下載版本的功能與 API 請以其程式碼為準。

## 使用方式

1. HR／管理員登入後，開啟「招募設定」。
2. 在「標準職稱」維護職稱代碼與正式名稱。一般申請人只能從啟用的選項選取。
3. 在「簽核流程」設定適用部門、關卡順序及各關指定簽核人。
4. 建立人力需求時選擇標準職稱與流程，預覽簽核路徑後儲存、送審。
5. 簽核人從人力需求的「待我簽核」入口查看待辦。上一關核准後，下一關才能處理。
6. 最後一關核准後，系統才會建立職缺。退回需填理由，申請人可修改後重新送審；拒絕則結束申請。

## 範本與執行紀錄

- 支援 1–8 關循序簽核，每關指定一人，同一人不重複出現在同一流程。
- 主管僅能簽核自己部門；包含主管的範本必須設定其所屬部門。
- 流程至少包含一位 HR 或管理員，以作為建立職缺後的負責窗口。
- 送審時複製流程名稱、版本、關卡及簽核人姓名，形成獨立快照。
- 範本更新或停用不影響已送審案件；下一次送審使用當時啟用的範本。
- 退回後重送建立新一輪，舊輪次的決定、理由與未執行關卡仍保留。
- API 檢查目前關卡 ID，並對申請資料取得資料庫寫入鎖，避免過期或重複請求誤處理後續關卡。

## 標準資料

- 標準職稱以 ID 關聯人力需求與職缺；名稱保留作為業務資料快照。
- 代碼與正規化名稱不重複，會比對英文字母大小寫、全半形與空白差異。
- 名稱與代碼建立後固定；可停用，停用後不再接受新選取或送審。
- 語意相近的別名仍由 HR 管理，例如是否將某種職稱併入既有職稱，應由公司統一規範。
- 部門、簽核人、面試方式與狀態使用既有標準選項；Offer 幣別限 TWD、USD、JPY、EUR。
- 需求原因、工作內容、自傳、原始任職經歷等描述資料保留文字輸入。

## API

- GET /api/recruitment-settings
- POST /api/recruitment-settings/job-titles
- PUT /api/recruitment-settings/job-titles/{id}/status
- POST /api/recruitment-settings/workflows
- PUT /api/recruitment-settings/workflows/{id}
- GET /api/requisitions/options：回傳標準職稱與適用流程。
- POST／PUT /api/requisitions：使用 jobTitleId、workflowTemplateId。
- POST /api/requisitions/{id}/review：使用 decision、reason、approvalStepId。
- GET /api/requisitions?pendingMine=true：在既有資料權限範圍內查詢待我簽核。

設定維護僅限 HR／管理員；關卡處理另檢查指定簽核人。前端隱藏選項不能取代後端驗證。

## 資料庫升級

Flyway V11 新增職稱主檔、流程範本、範本關卡與申請簽核快照。既有需求與職缺保留原名稱及時間，啟動時補上職稱關聯。既有待審需求在可用的標準 HR 流程下補上指定關卡；已完成資料保留原有歷程。

標準職稱與預設流程僅在空表時初始化，不會重新啟用已停用設定。
